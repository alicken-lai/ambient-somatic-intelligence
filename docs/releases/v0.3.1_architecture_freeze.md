## 1. Cognitive Ontology Snapshot

The v0.3.1 memory ontology defines a strict 4-layer hierarchy for knowledge maturation:

| Layer | Name | Description | Retention | Max Entries |
|-------|------|-------------|-----------|-------------|
| **L1** | Episodic | Raw episodic memory — unprocessed observations and events (sessions, logs, sensor events, transcripts, execution traces) | 30d | 10,000 |
| **L2** | Instinct | Atomic reusable observations distilled from episodic patterns (trigger rules, confidence, contextual applicability) | 180d | 5,000 |
| **L3** | Skill | Clustered workflows and procedures validated across contexts (reusable procedures, compound operational patterns) | 365d | 1,000 |
| **L4** | Strategic | Decision heuristics and metacognitive rules — highest-trust memory (routing philosophies, escalation principles) | unlimited | 200 |

**Implementation:** `memory/ontology/layer_definition.py` — `MemoryLayer(IntEnum)`, `LAYER_REGISTRY: dict[MemoryLayer, LayerDefinition]`

## 2. Promotion Doctrine

All promotions are **proposed only** and require explicit governance approval. There is no auto-promotion.

| Transition | min_confidence | min_occurrences | min_success_rate | cross_context | governance | verifier |
|------------|---------------|-----------------|------------------|---------------|------------|----------|
| **L1 → L2** | 0.7 | 3 | 0.0 (not required) | No | No | No |
| **L2 → L3** | 0.8 | 5 | 0.7 | Yes | Yes | No |
| **L3 → L4** | 0.9 | 10 | 0.85 | Yes | Yes | Yes |

**Implementation:** `memory/ontology/promotion_rules.py` — `PROMOTION_RULES: list[PromotionRule]` (3 rules)

**Key enforcement points:**
- `check_promotion_eligibility()` returns `(eligible: bool, blocking_reasons: list[str])`
- Occurrence count extracted from `access_count`, `occurrence_count`, or `execution_count` attributes
- Cross-context check requires `contextual_applicability` or `contexts_validated` length > 1
- L3→L4 promotion additionally requires `verifier_id` in `PromotionEngine.approve_promotion()`

## 3. Decay Doctrine

Exponential decay formula: `confidence *= exp(-rate × elapsed_days)`

| Layer | base_rate/day | inactivity_multiplier | inactivity_threshold | contradiction_penalty | min_confidence |
|-------|--------------|----------------------|---------------------|-----------------------|----------------|
| **L1 Episodic** | 0.1 | 2.0× | 7d | 0.05 | 0.01 |
| **L2 Instinct** | 0.03 | 1.5× | 30d | 0.10 | 0.05 |
| **L3 Skill** | 0.01 | 1.3× | 90d | 0.15 | 0.10 |
| **L4 Strategic** | 0.003 | 1.1× | 365d | 0.20 | 0.20 |

**Implementation:** `memory/ontology/decay_rules.py` — `DECAY_RULES: list[DecayRule]` (4 rules), `DECAY_RULE_REGISTRY: dict[MemoryLayer, DecayRule]`

**DecayEngine actions** (`memory/ontology/decay_engine.py`):
- `apply_time_decay()` — exponential decay based on elapsed time
- `apply_inactivity_decay()` — accelerated decay when inactive beyond threshold
- `apply_contradiction()` — immediate confidence penalty
- `apply_failed_reuse()` — penalty on bad execution outcome
- `sweep()` — full decay pass (time + inactivity + threshold check)
- `get_at_risk_entries()` — entries within 0.1 margin of removal threshold

**Recommended actions per confidence level:**
- `confidence <= min_confidence` → `remove`
- `margin < 0.1` → `archive`
- Otherwise → `retain`

## 4. Verification Doctrine

> *"The implementer is an LLM. Verify independently."*

**The Four Verification Axioms:**

| # | Axiom | Enforcement |
|---|-------|-------------|
| 1 | The implementer cannot self-certify | `ConfidenceValidator.is_self_certification()` raises `ValueError` |
| 2 | The verifier must be independent | `implementer_id != verifier_id` enforced in `submit_verification()` |
| 3 | Verification confidence must be tracked | `VerificationResult.confidence` recorded in audit trail |
| 4 | Low confidence blocks promotion | `min_verifier_confidence = 0.7` in `VerificationPolicy` |

**Layer-specific rules:**
- L1 can self-certify (`max_self_certification_layer = 1`)
- L2+ requires independent verification
- Verification expires after 30 days (`max_verification_age_days = 30`)
- Low confidence triggers escalation when `escalate_on_low_confidence = True`

**Implementation:** `governance/doctrine/confidence_validation.py` — `ConfidenceValidator`, `VerificationRequest`, `VerificationResult`, `VerificationPolicy`

**Verification confidence thresholds:**
| Promotion | Min Verification Confidence |
|-----------|----------------------------|
| L1 → L2 | 0.60 |
| L2 → L3 | 0.70 |
| L3 → L4 | 0.90 |

## 5. Skillify Doctrine

**8-Stage Pipeline:**

```
Observe → Mine → Cluster → Generate → Validate → Propose → Approve → Register
```

| Stage | Component | Path | Description |
|-------|-----------|------|-------------|
| 1. Observe | `WorkflowObserver` | `agents/skillify/workflow_observer.py` | Passive L1 event capture to `observations.jsonl` |
| 2. Mine | `SkillifyPatternMiner` | `agents/skillify/pattern_miner.py` | Detect recurring patterns via frequency analysis |
| 3. Cluster | `WorkflowCluster` | `agents/skillify/workflow_cluster.py` | Group related instincts by weighted similarity |
| 4. Generate | `SkillCandidateGenerator` | `agents/skillify/skill_candidate_generator.py` | Transform clusters into formal `SkillCandidate` objects |
| 5. Validate | `SkillCandidateValidator` | `agents/skillify/skill_candidate_validator.py` | Criteria + simulation-based validation |
| 6. Propose | `SkillRegistrationPipeline.propose()` | `agents/skillify/skill_registration_pipeline.py` | Submit to governance review queue |
| 7. Approve | `SkillRegistrationPipeline.approve()` | `agents/skillify/skill_registration_pipeline.py` | Independent reviewer renders decision |
| 8. Register | `SkillRegistrationPipeline.register()` | `agents/skillify/skill_registration_pipeline.py` | Skill enters `SkillRegistry` |

**Constitutional constraints:**
- Skillify may **propose only**, never auto-register
- Skillify must never call `approve()` on its own proposals
- All promotions are governance-gated
- Rollback is always available via `SkillRegistrationPipeline.rollback()`

**Evolution doctrine documents:**
- `agents/skillify/doctrine/observation_to_instinct.md` — L1 → L2
- `agents/skillify/doctrine/instinct_to_skill.md` — L2 → L3
- `agents/skillify/doctrine/skill_to_strategy.md` — L3 → L4

## 8. Known Risks

| # | Risk | Severity | Detail |
|---|------|----------|--------|
| 1 | `schema.json` `additionalProperties: false` | MEDIUM | Adding new fields to existing schemas will fail validation; new ontology fields must not conflict with existing JSON schemas |
| 2 | Skillify `governance_level` mismatch | LOW | `SkillCandidateGenerator` uses `"BLOCK"` but `SkillValidator` expects `"BLOCK_WITHOUT_APPROVAL"` — invalid governance level will fail schema validation |
| 3 | `_try_skill_registry` dict mismatch | LOW | Passes raw `dict` instead of typed `SkillInput`/`SkillOutput` objects to the skill registry |
| 4 | 6/7 bus connections use monkey-patch | MEDIUM | Only `somatic_to_salience` uses callback; the other 6 connections replace methods at runtime, making debugging harder |
| 5 | `access_counts.json` always empty | LOW | File exists but is never populated by runtime code |
| 6 | Memory Palace is static snapshot | LOW | `mempalace/` content is a pre-built snapshot; no runtime process updates it |

## 9. Unsupported Behaviors

What the system explicitly does **NOT** do:

| Behavior | Status | Constraint Source |
|----------|--------|------------------|
| Auto-promotion | NOT SUPPORTED | All promotions require governance; `PromotionEngine` only proposes, `approve_promotion()` requires `governance_decision_id` |
| Self-certification for L2+ | NOT SUPPORTED | `ConfidenceValidator.is_self_certification()` enforced; `max_self_certification_layer = 1` |
| Corrective action from precursor detection | NOT SUPPORTED | `PrecursorMatcher` detects and signals but takes no corrective action |
| Automatic skill routing mutation | NOT SUPPORTED | `SkillRouter` routing table is static; no mechanism to auto-modify routing conditions |
| Live memory mutation from tests | NOT SUPPORTED | Tests use isolated fixtures; no test writes to production `memory/` or `state/` directories |

6. **No verification policy relaxation** without governance approval
7. **All existing tests must continue to pass** after any change
